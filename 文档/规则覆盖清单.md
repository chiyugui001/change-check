# 变更校验规则覆盖清单

关联：[文档目录](_INDEX.md)、[工具入口](../_INDEX.md)、[设计方案](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md)、[使用指南](%E4%BD%BF%E7%94%A8%E6%8C%87%E5%8D%97.md)。

## 1. 判定原则

脚本执行是机械规则的必经路径；AI 负责语义、授权和证据充分性。
所有检查模块遵循 [渐进式检查约定](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md#23-%E6%89%80%E6%9C%89%E6%A3%80%E6%9F%A5%E6%A8%A1%E5%9D%97%E7%9A%84%E5%85%B1%E5%90%8C%E7%BA%A6%E5%AE%9A)：脚本必检，AI 补充语义并按新增变化及影响范围增量执行；提交前必须完整覆盖暂存变更。
AI001～AI009 对应知识库，代码、配置和普通文档使用第 6 节规则；同模式分项增量验证见 [模块与增量验收](%E9%AA%8C%E8%AF%81%E8%AE%B0%E5%BD%95.md#incremental-review)。
下表保留规则的原始实现来源；当前接入结果与测试边界在文末记录。
技能条款按相同验收语义合并，未列入的新增条款需更新映射后才能宣称全覆盖。

## 3. 必须进行的语义审查

| 编号 | 审查内容 | 证据要求 |
|---|---|---|
| AI001 | 结论有来源，区分事实、建议与待确认 | 变动文档及所引用来源 |
| AI002 | 项目、客户、版本、模块职责及指定修改范围准确 | 当前文档、关联规范、模块文档与修改授权 |
| AI003 | 必要功能、触发条件、处理顺序、边界、异常恢复、验收及链接未遗漏 | 修改前后全文及需求覆盖映射 |
| AI004 | 接口、结构体、事件、状态、图表、配置与风险一致 | 当前详设及相关需求/协议 |
| AI005 | 从全文发现未决事项，核对原文与待办的对象、条件、完成标准、状态；确认方案不等于验证完成 | 原文位置、具体待办双链、确认记录和验证证据 |
| AI006 | Raw/active 修改、状态提升、新增或修改文档 version 有授权依据 | 基线、明确的用户授权记录；历史 version 未变化时不追责 |
| AI007 | REVIEW 候选逐项有结论，误报有理由 | 脚本候选编号与关联上下文 |
| AI008 | 不把源代码实现状态、静态检查或图谱关系冒充运行验证 | 来源版本、实现/设计边界和验证记录 |
| AI009 | 内容必要性与表达，逐段检查下表五项 | 具体原文、文档用途、已确认结论和必要执行规则 |

AI 缺少必要证据时标为未完成；不得让模型补造来源或默认为已有授权。

| 写作规则 | AI009 判定要求 |
|---|---|
| 保留必要内容 | 删除后不影响理解、实施和结果判断的句子、段落、示例、表格行应删除，即使它们没有重复 |
| 直接呈现选定方案 | 正式方案写最终结构、参数与处理；用户要求的分析和比较文档保留必要推导 |
| 明确业务对象 | 使用具体对象、动作、结果，检查泛称是否掩盖已有明确类型 |
| 直接陈述已确认事项 | 删除无执行价值的过程表述，保留真实前提和未完成验证状态；历史记录、合法引用不机械删改 |
| 集中说明同一规则 | 集中规则并建立引用；需求与验收间有执行价值的复述可以保留 |

七条写作规则中的执行边界与链接保全由 AI002、AI003、KB003 覆盖，文档版本授权由 KB007、AI006 覆盖。
普通正文的脚本适用范围见 [规则加载与复用](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md#4-%E8%A7%84%E5%88%99%E5%8A%A0%E8%BD%BD%E4%B8%8E%E5%A4%8D%E7%94%A8)；语义审查仍须阅读完整变动范围和相关记录。

结果协议要求九项 `rule_checks` 各有适用性和具体理由，适用项必须有文件及有效行范围。
每个 REVIEW 对应一个 `dispositions`，每个 KB008 对应一个 `pending_items`，分别保留候选编号、处置理由和原文位置；允许 AI 新发现事项使用空候选编号列表。
具体待办双链要求见 [未决事项关联](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md#93-%E6%9C%AA%E5%86%B3%E4%BA%8B%E9%A1%B9%E5%85%B3%E8%81%94)。位置存在和文字非空只是机械完整性，不证明语义判断正确。

## 4. 不互相替代的验证

- 标签脚本通过，不代表 Mermaid 可渲染；实际渲染需单独执行并记录。
- 覆盖映射链接有效，不代表需求语义保真；AI003 必须执行。
- 内容脚本返回 REVIEW，不代表存在真实重复；AI007 判断后再决定修改。
- AI 审查通过，不代表人工审核完成；保持原人工审核边界。

## 6. 通用模块规则

### 6.1 脚本与项目命令

| 编号 | 必检内容 | 能力边界 |
|---|---|---|
| CORE001～004 | 未匹配检查器、缺快照文本、冲突标记、禁止跳过 C 基础检查 | 未覆盖明确失败，不能由 AI 代替 |
| SCRIPT001 | Python 语法；JSON/YAML/TOML 解析和重复键；INI/CFG 解析 | 不自动推导业务配置 schema |
| DOC001 | 普通文档围栏闭合 | 不要求知识库属性；语义需 AI |
| C001～003 | 4 空格、禁 Tab；常见声明命名与变量前缀；函数/控制语句大括号位置 | 词法解析未覆盖全部 C 复杂声明 |
| C004～007 | 函数 50 行、5 参数、控制语句有括号且换行、嵌套 4 层 | 条件编译导致结构不确定时转 REVIEW |
| C008～011 | 禁 strcpy/gets；strncpy 终止候选；MODULE_XXX_H；函数内非 0/1 数字需命名 | 路径上 NULL 终止、宏展开和复杂初始化须语义核对 |
| C099 | 无法配对的词法结构 | REVIEW，不声称完成编译；使用项目编译器判断 |
| CMD001 | 项目命令缺失、失败、超时、输入改写或必需角色缺失 | 外部检查器对其实际格式/编译/测试负责 |

C 规则来自本任务提供的规范速查。约定的完整 `c_coding_standards.md` 在本机未找到，未宣称覆盖未读取文件中的额外条款。新增项目规范通过必检命令和规则来源配置接入。

### 6.2 AI 规则

| 编号 | 必审内容 |
|---|---|
| CODE001～004 | 需求和接口兼容；边界/错误/资源/并发安全；构建测试证据；脚本未证明的 C 规范 |
| CFG001～002 | 字段约束、消费方兼容；默认值、敏感信息和配置影响 |
| DOC_AI001～002 | 事实、需求保留、一致性；链接、未决事项和相关实现 |
| GEN001 | 外部检查器覆盖的其他格式、删除影响和依赖 |

公共协议按本次文件类型生成规则集合；混合变更取并集。知识库候选处置与待办映射继续强制执行；代码结果不能只提交九条文档规则冒充审查。
