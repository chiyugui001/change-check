# 变更校验工具使用指南

入口：[文档目录](_INDEX.md) · [工具目录](../_INDEX.md) · [设计方案](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md)。

## 1. 安装与登记

### 1.1 启动安装

准备 Python 3.11+、Git，以及已登录的 Claude Code 或 Codex CLI，然后在 PowerShell 运行：

```powershell
& 'C:\tools\change-check\install.ps1'
```

安装器建立独立 Python 环境，并按以下步骤接入检查：

| 步骤 | 操作 |
|---|---|
| 输入项目目录 | 留空使用终端当前目录：在 `PS C:\work\my-project>` 启动，默认就是 `C:\work\my-project`；也可输入其他路径，确认后自动登记 |
| 选择检查模块 | 默认自动选择；没有现成规范的新知识库可输入 `knowledge,code,config`，使用随包规则 |
| 选择编辑平台 | 从检测结果中选择 Codex、Claude Code、Kimi、ZCode，可多选 |
| 选择审查器和模型 | 单选 Claude Code/Codex 时默认跟随；Kimi/ZCode 需另选审查器。可修改向导显示的默认值；模型回车保留，输入 `-` 使用客户端默认 |
| 验证接入 | 按宿主要求信任钩子、新开会话并测试实际写入；使用 `doctor` 查看状态 |

“登记”只确定检查目录；安装向导同时配置自动触发。新增项目再次运行安装入口，已有选择会保留。独立 Git 仓库分别安装；非 Git 目录仅支持脚本检查。

独立包已包含基础规范、模板及校验脚本；你本机的现有来源优先使用。规范路径提示可直接回车，明确指定的路径失效会报错。维护及分发见 [发布指南](%E5%8F%91%E5%B8%83%E6%8C%87%E5%8D%97.md)。

### 1.2 当前验证状态

本地回归已通过；真实客户端事件和实际项目钩子仍需 [部署验收](%E9%AA%8C%E8%AF%81%E8%AE%B0%E5%BD%95.md#hook-acceptance)，真实模型效果仍需 [模型验收](%E9%AA%8C%E8%AF%81%E8%AE%B0%E5%BD%95.md#model-acceptance)。配置成功不等于接入已验证。

## 2. 日常检查与提交

### 2.1 自动检查

| 场景 | 执行方式 |
|---|---|
| 已接入 AI 修改文件 | 比较上次检查之后的新增差异，检查变化及必要关联，复用未受影响结果 |
| 确定错误 / 待复核候选 | 新错误即时简报；候选只在结束时汇总，不强迫 AI 反复续写。重复问题不重发，完整报告保留 |
| 本轮仅提问或阅读，没有新修改 | 结束钩子直接跳过项目读取和脚本检查；本轮写入尚有待发送摘要时只汇总一次 |
| 撤回此前修改 | 检查相对于最近检查版本的撤回影响 |
| 手动编辑文件 | 执行下面的手动检查，或在提交时检查 |
| Git 提交 | 必检脚本 → 独立 AI 审查 → 核对暂存内容，失败则停止提交 |

无需常驻后台。工具不会自动改写项目文件；修复后重新检查，提交前须重新暂存。工作区通过不能代替暂存版本通过。

从没有执行前钩子的版本升级时，重新运行安装器并新开 AI 会话；已接入会话事件且程序路径未变，只更新代码即可。并发归属不明、缺少事件或后台写入仍在执行时提示范围未确认，不扩大为全仓检查。语法、全文结构、重复内容和项目命令仍按必要的完整单元执行，手动 `--changed` 仍检查工作区全部未提交变动。

例如：新增步骤①②③并检查后，只删除③，下一次检查这次删除及其影响；①②未受影响的结果复用。旧问题继续保留，不能因这次没改到而视为解决。

### 2.2 手动命令

在当前 PowerShell 窗口先设置入口和实际项目路径；下文命令均使用这两个变量：

```powershell
$cc = 'C:\tools\change-check\change-check.ps1'
$checkProject = 'C:\work\my-project'
```

| 目的 | 命令 |
|---|---|
| 检查工作区变动 | `& $cc check --root $checkProject --changed` |
| 检查暂存内容 | `& $cc check --root $checkProject --staged` |
| 主动进行日常 AI 审查 | `& $cc review --root $checkProject --changed` |
| 手动执行提交门禁 | `& $cc gate --root $checkProject` |
| 只检查代码模块 | `& $cc check --root $checkProject --module code --changed`；不能代替完整门禁 |

日常钩子仅执行脚本；`review` 和 `gate` 才调用 AI，且要求登记目录是 Git 根目录。AI 由工具独立启动，不继承编辑聊天；必要的任务约束和授权应写入可读取资料。

## 3. 选择检查规则

| 项目情况 | 默认规则或配置要求 |
|---|---|
| 有约定的“知识库规范”目录 | 启用知识库、代码、配置模块；Markdown 按知识库规范检查 |
| 没有该目录 | 启用代码、配置、普通文档模块；普通文档不要求知识库属性 |
| C / Python | 内置 C 基础词法规则、Python 语法检查；不代表编译通过 |
| 编译、测试、其他语言 | 配置项目真实检查命令；没有适用检查器时阻断，不默认为通过 |

可覆盖模块选择，配置写入项目根的 `change-check.json`，应随项目提交：

```powershell
& $cc config --root $checkProject --modules 'code,config,document'
```

|---|---|
| 构建、测试命令及必检角色 | [配置字段与示例](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md#25-%E9%A1%B9%E7%9B%AE%E7%AD%96%E7%95%A5%E4%B8%8E%E5%91%BD%E4%BB%A4) |

## 4. 查看或修改审查模型

```powershell
& $cc reviewer --root $checkProject
& $cc reviewer --root $checkProject --kind claude --model '你的实际模型名'
& $cc reviewer --root $checkProject --use-default-model
```

设置按项目保存，无需重装钩子；切换审查器会清除旧模型及程序参数。内置审查器固定模型后才复用 AI 缓存；未固定仍可审查，但每次重新调用。

模型不存在、无权限、超时或调用失败会阻止提交，不自动换模型；保存配置不验证模型可用性，实际调用以 [模型验收](%E9%AA%8C%E8%AF%81%E8%AE%B0%E5%BD%95.md#model-acceptance) 为准。 <a id="model-selection"></a>

## 5. 管理项目与报告

| 操作 | 命令 |
|---|---|
| 查看已登记目录 | `& $cc list` |
| 仅登记目录，不安装钩子 | `& $cc add $checkProject`；启用自动检查仍需运行安装入口 |
| 移除一个目录及其接入 | `& $cc remove $checkProject` |
| 卸载全部接入 | `& $cc uninstall`；保留项目文件和其他插件配置 |
| 查看报告占用与保留策略 | `& $cc storage` |
| 预览清理 / 执行清理 | `& $cc cleanup --dry-run` / `& $cc cleanup` |

报告默认在 `%LOCALAPPDATA%/change-check/`，按工作区与暂存审查分开保存；默认保留 30 天，生成记录合计上限 200 MiB。数量限制、例外和参数见 [保留策略](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md#34-%E7%94%9F%E6%88%90%E8%AE%B0%E5%BD%95%E4%BF%9D%E7%95%99)。

日常会话完整报告位于提示路径中的 `cache.report`；停止重复提醒不代表候选已通过审查。

重装、移动入口或从 `kb-check` 升级，按 [更新说明](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md#103-%E7%8E%AF%E5%A2%83%E6%9B%B4%E6%96%B0%E4%B8%8E%E5%8D%B8%E8%BD%BD) 操作；旧注册表沿用时以安装输出的实际目录为准。

## 6. 问题处理

| 问题 | 处理 |
|---|---|
| 未触发、缺程序/技能/模板 | 运行 `& $cc doctor`；核对路径、登录、钩子信任及实际事件，按报告修正 |
| 脚本 ERROR / 缺少检查器 | 修复错误或配置对应必检命令，再运行检查 |
| REVIEW 候选 | 查看原文与依据，由 AI 逐项判断；不直接视为错误。KB007 核对版本授权，KB008 核对 [具体待办双链](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md#93-%E6%9C%AA%E5%86%B3%E4%BA%8B%E9%A1%B9%E5%85%B3%E8%81%94) |
| 提交仍报告旧错误 | 确认修复已暂存；失败后保留原暂存内容，修正后再提交 |
| AI 报错或证据不足 | 核对请求模型和客户端错误，补齐来源及约束后重试；不以旧通过记录放行 |
| 原有钩子失败 / 卸载冲突 | 按原钩子或冲突报告处理，保留其他工具和用户配置 |

其他参数可执行 `& $cc check --help` 等命令查询。需要 [自定义审查器](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md#917-%E8%87%AA%E5%AE%9A%E4%B9%89%E5%AE%A1%E6%9F%A5%E5%99%A8%E5%8D%8F%E8%AE%AE)、[非交互部署](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md#101-%E5%AE%89%E8%A3%85%E6%B5%81%E7%A8%8B) 或 [运行测试](%E9%AA%8C%E8%AF%81%E8%AE%B0%E5%BD%95.md#11-%E8%BF%90%E8%A1%8C%E6%9C%AC%E5%9C%B0%E5%9B%9E%E5%BD%92) 时再查对应章节。
