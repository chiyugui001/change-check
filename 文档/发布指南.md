# 变更校验工具发布指南

关联：[文档目录](_INDEX.md)、[工具入口](../_INDEX.md)、[仓库首页](../README.md)、[使用指南](%E4%BD%BF%E7%94%A8%E6%8C%87%E5%8D%97.md)、[设计方案](%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%A1%88.md)、[验证记录](%E9%AA%8C%E8%AF%81%E8%AE%B0%E5%BD%95.md)。

## 1. 只维护源文件

| 对象 | 维护位置 | 发布处理 |
|---|---|---|
| 工具代码 | `src/`、`tests/`、`packaging/` | 按允许清单导出 |
| 规范、模板 | 现有知识库规范目录与模板目录 | 自动生成 `resources/standards/`、`resources/templates/` |
| 校验脚本、技能审查条款 | 原有技能目录 | 自动收集七个脚本、四份技能说明及八份参考文档 |
| 本机来源映射 | `packaging/sources.local.json` | 只用于打包，不提交、不进入独立包 |
| 生成副本 | 发布目录的 `resources/` | 禁止手工修改；清单记录源文件和生成文件的 SHA-256 |

本机项目规范和已有技能优先；其他电脑使用随包资源。明确指定的路径缺失时直接报错，不切换到旧副本。普通代码项目不会因存在随包规范而自动启用知识库规则。

## 2. 生成独立包

首次复制 `packaging/sources.example.json` 为 `packaging/sources.local.json`，填写原规范、模板及四项技能的目录。来源文件缺失会停止打包。

在工具目录运行：

```powershell
& '.\.venv\Scripts\python.exe' -B -X utf8 '.\packaging\build.py' --sources '.\packaging\sources.local.json'
```

| 产物 | 用途 |
|---|---|
| `dist/<时间>/change-check/` | 可独立安装的目录；也是提交 GitHub 的发布内容 |
| `change-check.zip` | 给其他电脑解压安装 |
| `change-check.zip.sha256` | 压缩包校验和 |
| 目录内 `SHA256SUMS.txt` | 发布文件校验和 |

源文件更新后，重新执行同一命令即可生成新版。已有输出目录非空时拒绝覆盖，可用 `--output` 指定新目录。原规范和技能不会被打包程序改写。

从 GitHub 克隆的目录已带 `resources/`；不提供 `--sources` 时只校验并重新包装现有副本，不访问维护者电脑，也不会获得尚未发布的源文件更新。发现生成资源被手工改动时拒绝重新打包。

## 3. 公开发布范围

| 内容 | 处理规则 |
|---|---|
| 程序、测试、工具文档、必要规则 | 进入独立目录；工具文档双链转换为相对 Markdown 链接 |
| 本机路径和示例标识 | 在生成文档中替换为通用路径和示例；来源文件保持原样 |
| 知识库正文、客户资料、映射表、登记信息、报告、缓存、凭据、虚拟环境 | 不在打包允许清单内 |
| 常见凭据或实际用户路径 | 扫描命中则停止，只报告文件名；扫描不替代人工复核 |

公开仓库只提交打包输出的 `change-check/` 内容，不提交整个知识库，也不提交本机来源映射。后续规则修改仍在源文件完成，再重新生成发布目录。

仓库：[chiyugui001/change-check](https://github.com/chiyugui001/change-check)。`.gitattributes` 保持文件原始换行，避免 Git 克隆时改变资源校验和。

## 4. 更新与验证

| 场景 | 操作 |
|---|---|
| 其他电脑安装 | 将独立目录放在固定位置，在项目目录运行 `install.ps1`；知识库项目可在向导选择 `knowledge,code,config` |
| 其他电脑更新 | 更新同一工具目录，重新运行安装器并新开 AI 会话以加载新增事件；脚本与规则内容变化会使旧检查缓存失效 |
| 搬动已安装的工具目录 | 从新位置重新安装并核对登记路径；显式旧路径失效会报错，需要更新 |
| 本地测试 | 使用 [回归命令](%E9%AA%8C%E8%AF%81%E8%AE%B0%E5%BD%95.md#11-%E8%BF%90%E8%A1%8C%E6%9C%AC%E5%9C%B0%E5%9B%9E%E5%BD%92)；独立包专项覆盖隔离用户安装、真实脚本执行、缺失资源阻断和可重复打包 |

知识库模块采用工程知识库约定，草稿需具备属性和 `PENDING-REVIEW.md` 等结构。工具提供检查资源，不自动创建或改写项目正文。真实宿主事件和实际模型效果仍按 [接入与模型验收](%E9%AA%8C%E8%AF%81%E8%AE%B0%E5%BD%95.md#4-%E5%90%8E%E7%BB%AD%E5%AE%9E%E6%96%BD%E4%B8%8E%E9%AA%8C%E6%94%B6%E5%BE%85%E5%8A%9E) 执行。
