# 模板选择

只在生成或更新知识文档时读取本文件。

## 唯一模板来源

正文和 Frontmatter 以目标知识库当前 `模板/` 与 `知识库规范/` 为唯一来源。本文件不复制模板内容，避免两套模板随时间分叉。

常见映射仅用于帮助查找，实际以目标库存在的文件为准：

| 知识类型 | 优先查找 |
|---|---|
| 需求 | `模板/需求.md` |
| 详设 | `模板/详设.md` |
| 测试 | `模板/测试.md` |
| 决策 | `模板/决策.md` |
| Bug | `模板/Bug.md` |
| 协议 | `模板/协议.md` |

## 使用规则

1. 先读 Frontmatter、命名、双链和图表规范，再读对应模板。
2. 保留模板规定的语言、章节编号和必填部分；按模板注释删除确实不适用的可选章节。
3. 不把 `type`、`platform`、`project`、`confidence`、`source_file`、`compile_date` 等字段从旧技能模板带入新文档，除非现行 Frontmatter 规范已经正式允许。
4. 编译来源、hash、模板版本等内部数据写入编译索引。文档需要表达溯源时，只使用规范允许的 `source`、`git_branch`、`git_commit` 等字段或正文来源章节。
5. 没有对应模板时，先复用最接近的已审核文档结构并报告差异；如果需要新知识类型或新 Frontmatter 字段，先修改知识库规范并经过用户确认，不得在单篇产物中试运行私有 schema。

## 内容最低要求

- 需求：背景、目标、范围边界、场景、影响模块、功能详情、边界、风险、可测试验收标准。
- 详设：需求链接、职责边界、接口、关键逻辑、状态/时序、依赖、参数、硬件约束、风险和源码定位。
- 决策：背景、选项、选择原因、淘汰原因、风险、兼容性和历史问题。
- Bug：现象、复现/触发、根因证据、影响、修复理由、防复发和关联需求/详设。
- 协议：适用范围、字段、单位/范围、时序、错误处理、版本兼容和上下位机影响。

缺少证据的必填内容标为“待确认”，不能为了填满模板而编造。
