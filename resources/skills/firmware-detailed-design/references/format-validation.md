# 全文格式校验

使用 `scripts/validate_detailed_design_format.py <详设路径> --template <当前模板路径>`。
支持多个详设路径、`--json`、非源码文档的 `--non-source`，以及文字长度阈值参数。
脚本只读；退出码 0 表示本脚本的机械检查通过，1 表示存在 ERROR/REVIEW，2 表示参数、模板或文件读取错误。

## 检查范围

| 规则 | 检查内容 |
|---|---|
| F001 | 标题层级、编号深度、父子编号、唯一一级标题 |
| F002 | 表头、分隔行和数据行列数，空表格 |
| F003 | 代码围栏、HTML 注释及 Frontmatter 闭合 |
| F004 | 从当前模板提取固定章节，检查名称、层级、编号、顺序及缺失；模板外章节列为 REVIEW |
| F005 | 枚举、结构体、函数、事件、调试指令和日志逐项小节、分隔线、必要说明块及顺序 |
| F006 | 当前模板表头、必要表格及模板/技能明确允许的变体 |
| F007 | 空说明块、必要代码围栏、带载荷事件的访问说明候选 |
| F008 | 待确认复选框、每项一张缩进表格、表头、固定行及顺序、必填内容、表后结论；未确认留空，已勾选填写实际结论 |
| F009 | 第 1.2 依赖关系图、状态图、时序图进入/退出 Note 及位置、分支闭合、alt/opt 有效嵌套不超过两层、激活区间及文字宽度 |
| F010 | 复用文字长度脚本，默认单行/整项 120、连续段落 200 个可见字符 |
| F011 | 复用 Frontmatter 解析和值校验，按指定模板检查字段集合及顺序 |
| F012 | 正文或标题残留当前模板中的中文占位符；代码参数记法不按正文占位符处理 |
| F013 | 图中代码名称的首行中文意图、换行与展示顺序；无法自动覆盖的图类型或节点语法报 REVIEW |

表格和固定章节取自本次传入的模板，不从待检文档反推标准。
动态的类型、函数、事件、指令、日志名称不与模板占位符逐字比较。
围栏代码和 HTML 注释不参与正文标题、表格和待确认项扫描。

## 允许的省略与变体

- 枚举表可以省略无独立内容的“取值限制”列；无独立规则时可省略枚举值规则块。
- 结构体字段约束、实例与访问按实际需要保留；普通、配置、函数指针字段表使用各自列结构。
- 无参数接口明确写“无输入参数”；函数异常处理仍使用技能要求的四列表格。
- 外部注册可使用“订阅示例”；零载荷事件可省略载荷访问规则，类型引用不强制复制载荷字段表。
- 无独立状态机时明确说明；两个业务状态可仅用模板迁移表，表头、迁移行及状态数量纳入 F009 校验；多状态模块提供状态图。简单模块可以省略关键时序，无额外跨对象约束时可省略并发表。
- 非源码详设可按模板约定省略模块文件组成和源码 Frontmatter 字段。
- 无配置、指令、日志、待确认项或风险时明确写“无”；不能用“无”代替第 1.2 依赖关系图等必要结构。
- 配置生效时机可按模板拆为配置事务完成时机和模块应用时机；日志时点总览可省略，实际日志仍逐项定义。
- 待确认采用当前模板的两种表格：有候选行为用“对比项、共同条件、场景 A、场景 B”，只缺信息用“项目、说明”。A/B 表头可追加冒号及具体行为，不允许任意换列名或列数。
- 固定行及顺序从模板提取，每行只能出现一次且须有实际说明；非固定行按需增加。对比表至少有一行包含实际的共同条件及 A/B 内容，不强制数字时间点；纯信息表无需候选场景。
- 每项只保留一张缩进表格和表后结论，不能用说明字段替代表格、把结论放进表内或填占位结论。无场景差异的单元格可填“—”，必填说明不能仅填“—”“待确认”等占位。
- 兼容性仅由传入模板决定：显式声明旧字段列表或旧时间表的历史模板仍按原规则检查；当前模板未声明的旧格式不能通过。旧时间表仍检查两个不同时间点，新通用对比表不继承该要求。
- 表格归属、列数、必填内容及结论状态由脚本检查；配置是否齐全、计时计算、假设是否合理、独立选择是否清楚及 A/B 是否确有决策差异由人工复核。

## 图表意图标签

- 全文格式校验自动调用 `scripts/validate_diagram_labels.py` 中的规则。单独审核架构文档、其他 Markdown 或 `.mmd` 时，运行 `python <技能目录>/scripts/validate_diagram_labels.py <文档路径> [其他文档路径] --json`，无需详设模板。脚本只读，退出码仍为 0 / 1 / 2。
- 自动检查 `flowchart/graph` 常见节点与边标签、`sequenceDiagram` 参与者与消息、`stateDiagram` 状态及迁移标签；识别函数、下划线标识符、源码文件/路径及独立英文标识符。标签必须先说明中文意图，再用 `<br/>` 或实际可显示的换行保留代码名称。
- 只显示代码名、未分行、代码名称在首行或顺序颠倒报 `F013 ERROR`。源码中的内部连线 ID、注释和样式不作为可见标签；纯业务概念及“UART/NFC 交互”等协议简称不强制补函数名。
- 未支持的图类型、新版节点属性语法和无法完整解析的节点报 `F013 REVIEW`。常见语法检查不是完整 Mermaid 解析；其他复杂语法、业务术语与短标识符的区分、代码名称拼写、中文意图和调用顺序须人工复核。不得把脚本未报错等同于全部语义通过。
- 按“文档路径 + 图序号”分别记录标签格式、语义复核和实际渲染结果。修正 ERROR，逐项处理 REVIEW；未检查项不得记为通过。渲染成功不能替代意图标签检查。

## 校验后的处理

逐条修正 ERROR，按具体上下文复核 REVIEW；修正后重新运行并保留结果。
只增加校验能力时，可用现有文档生成报告，不借机重写所有历史文档。
文档局部修订需披露全文历史问题；未解决的全文问题不能被表述成“全文符合模板”。

本脚本覆盖全文中可机械判定的格式；条件完整性、表述是否重复、字段归属和图是否准确仍由对应脚本候选及人工复核处理。
Mermaid 检查为基础格式检查，不是完整语法解析或渲染验证；有渲染工具时仍须实际渲染。
自定义模板改变章节用途或增加复杂条件格式时，应更新校验支持和回归用例，不能为让脚本通过而改写模板。
