# 固件详设复核清单

仅在完整编写、系统性修订或正式复核时读取。本清单用于发现设计缺口，不替代当前知识库模板。

## 1. 证据与范围

- [ ] 已确认知识库、项目库、源码仓库和目标文件，没有从历史路径猜测。
- [ ] 已读取当前库规范、详设模板、项目索引和相关需求。
- [ ] 已查询可用知识图谱，再按调用链读取必要源码。
- [ ] 已锁定源码分支和提交；`source` 是可访问且可追溯的链接。
- [ ] 模块、任务、函数、事件和类型名称已回到锁定源码或已确认目标设计核对；没有把历史图谱名称当成当前事实。
- [ ] 产品要求、源码事实、硬件推断、设计建议和未决问题可以区分。
- [ ] 来源冲突没有被静默合并。
- [ ] 文档只覆盖一个可独立检索的职责主题。

## 2. 章节职责

### 模块概述与边界

- [ ] 对应需求使用标题锚点链接，且没有复制整份需求。
- [ ] 没有单独设置“设计目标”小节；工程结果和关键约束已落入对应的接口、逻辑、时序、配置或风险章节，没有在概述中重复汇总。
- [ ] 第 1.2 依赖关系图以 `subgraph` 分出“上游输入与请求”和“下游使用方”，两者之间明确标出本模块；图体现实际存在的通知分发和查询依赖，全文没有第二张依赖关系图。
- [ ] 职责边界明确“本模块负责”和“其他模块负责”。
- [ ] 模块文件组成只列职责属于本模块的源文件和头文件；没有把调用方、通知分发、参数管理、协议解析、板级驱动或下游模块文件混入本模块。
- [ ] 模块输出业务事实、动作请求或引用时，没有越界定义下游执行细节。
- [ ] 正文中的资源、表、缓存和内部对象先使用通用设计名称；文件内变量名、静态对象名或数组名仅作为括号说明或独立“实际变量名”列，没有单独代替设计概念。
- [ ] 表格中的发布方、接收方、所有者、组件、依赖对象、运行位置和传递方式先说明通用角色或职责；实际函数名、模块名、任务名、接口名和类型名仅作为括号说明或独立映射列，没有只填一个 C 标识符。

- [ ] 运行上下文覆盖主循环、任务、中断、定时器、DMA 或回调等实际参与者；省略该章时，这些约束仍在时序与并发章节完整体现。
- [ ] 时序图使用真实或已确认的任务名和执行上下文，没有虚构协调器、适配层或任务名称。
- [ ] 时序图中的本模块内部参与者均能回溯到模块文件组成中的运行时代码文件或已确认内部组件；只提供声明的头文件没有被画成运行时参与者。
- [ ] 跨模块时序止于稳定接口或事件，没有展开其他模块的内部解析、持久化或执行逻辑。
- [ ] 完全属于外部模块的配置、调度、通知分发或消费流程使用边界文字或关联详设说明，没有为补齐链路画入本模块时序图。

- [ ] 每张 `sequenceDiagram` 都在本模块最后一个调用或返回箭头之后使用 `Note` 明确说明退出条件；图在本模块稳定边界结束，没有展开调用方返回后的任务循环、队列调度或下游内部处理。
- [ ] 多个任务、ISR、定时器或回调上下文已使用 `box` 分组；本模块函数或回调使用成对的 `activate/deactivate` 标出实际执行区间，单一上下文没有机械增加无意义分组。
- [ ] 同步箭头从实际执行方继续并由返回箭头闭合；异步消息使用虚线箭头并说明入队、唤醒和载荷语义，没有画成发布方直接调用接收任务，也没有为通用通知分发虚构本模块参与者。
- [ ] `alt/opt` 没有相互嵌套；包含进一步决策的分支已拆成子图，单执行单元内部的算法和结果映射使用对应函数说明中的 `flowchart` 或决策表，提前终止路径优先使用 `break`。
- [ ] 时序图普通文本每行不超过 40 显示列；`Note` 每行不超过 40 乘以实际跨越生命线数量的显示列。汉字按 2 列、英文字母/数字/符号按 1 列核算，换行没有拆开函数名、事件名或字段名。
- [ ] 时序图对影响后续判断或输出的关键读取使用浅蓝背景，对清空、保存、替换、更新等关键写入使用浅橙背景；章节开头说明颜色语义，普通调用、返回、校验、纯计算和事件发布没有被过度高亮。
- [ ] 保留执行上下文汇总表时，表中写明阻塞限制、调用周期/优先级和 ISR 禁止操作；接口详细定义已覆盖时没有机械重复。
- [ ] 函数调用方式位于函数详细定义，事件触发方式位于事件详细定义；时序与并发章节没有重复充当接口目录或“运行方式”汇总。
- [ ] 依赖关系图只画上游、模块调用方、本模块、板级接口和下游模块之间的稳定边界；上游事件、服务请求、查询依赖和输出事件的箭头方向与实际调用、交付方向一致。
- [ ] 配置、定时器或通知分发不直接调用本模块文件时，依赖图保留“模块调用方”边界，没有把外部职责直接画入本模块；下游图止于订阅或交付边界，没有展开消费者后续处理。
- [ ] 依赖图边标签先写业务意图；需要对应代码时换行显示真实名称，并用引号保护函数括号。函数原型、参数和返回值位于接口定义。

### 对外接口与数据结构

- [ ] 概览只列跨模块稳定契约，未混入内部辅助函数或内部事件。
- [ ] 通用通知分发、队列发送和参数存取等依赖接口没有被列成本模块对外接口。
- [ ] 每个名称是具体的 C 标识符或通知类型，不是中文占位描述。
- [ ] 函数标识符作为接口名称、小节标题、表格项或正文引用时统一带 `()`；函数原型保留真实参数，函数指针字段、回调类型、宏、事件、变量、文件名和类型名没有误加括号。
- [ ] 新接口和新角色的命名在形成定稿契约前已明确标为建议并完成确认；正文没有把推测名称写成项目既有概念。
- [ ] 关键数据结构位于函数和事件详细定义之前，接口原型引用的类型可先阅读。
- [ ] “关键数据结构”只展开本模块定义的类型，以及由本模块负责维护的跨模块稳定契约；每个枚举和结构体各自使用一个小节，并按类型依赖和职责排列；没有因为定义相邻、复用基础类型或共用代码块而合并不同类型。

- [ ] 结构体定义前增加用途注释，每个成员增加就近的 C 注释；将字段表“含义”和“具体内容”（存在时）完整补入对应注释，保留其中的单位、范围、特殊值、条件和限制。“同上”等依赖表格位置的表述须展开；表格保留，注释与表格同步维护，属于必要重复。

### 逻辑、状态和时序

- [ ] 函数详细定义、状态迁移和时序图中的条件、动作及输出一致。
- [ ] 初始化、首次确认、重复输入、超时、禁用、配置切换和恢复均有定义。
- [ ] 状态机只包含业务状态；配置加载、重建缓存和重新计算等处理步骤未被写成状态。
- [ ] 只有两个业务状态时直接使用迁移表；多状态模块使用 `stateDiagram-v2`，表格仅补充图中难以清晰表达的规则。迁移条件和动作完整，异常处理可引用对应接口，图、表与文字不重复；设备复位、启动初始化等生命周期过程归入对应接口。
- [ ] 稳定输入等统一前置条件只说明一次，没有在每条转换中机械重复。
- [ ] 迁移条件与迁移动作没有颠倒；建立基线、更新输出和发布通知属于动作。
- [ ] 配置切换和运行时重算放在配置流程或时序中，没有污染业务状态机。
- [ ] `flowchart` 仅用于对应函数说明中的复杂分支，`stateDiagram-v2` 用于第 3 章状态迁移，`sequenceDiagram` 用于多角色时序。
- [ ] 单图保持可读；复杂流程按职责或阶段拆图。
- [ ] 所有时序数值都有需求、协议、硬件、调度预算或实测依据。

### 配置参数

- [ ] 每项配置有唯一权威来源，不存在两个互相矛盾的使能或默认值。
- [ ] 默认值、合法范围、单位、越界处理和生效时机明确。
- [ ] 配置章节直接命名为“配置参数”；仅有一张配置表时没有重复设置同名子标题。
- [ ] 配置表“参数”列使用中文业务名称，实际字段只写在独立“变量名”列，没有用 C 变量名代替参数含义。
- [ ] 配置参数表与关键数据结构中的配置结构体逐字段一致；参数表没有被用来替代配置结构体的 C 类型定义和所有权说明。
- [ ] 配置表每列只表达一个概念；只有写入生效与业务采用确有时间差时才分列，共同生效规则没有逐行重复。
- [ ] 功能详设没有设置“持久化设计”章节；参数存储布局、主备份、完整性校验、升级迁移和写入寿命归入参数管理或存储设计文档。
- [ ] 配置读取、运行时采用和失败返回契约完整；没有用源码现状或实现缺口代替目标契约。
- [ ] 配置切换期间的输入事件顺序、屏障和旧事件处理明确。
- [ ] 没有为规避未分析的竞态自行增加配置代次或版本字段；若确需版本标识，比较规则、溢出处理和存储代价完整。

### 并发与失败处理

- [ ] 单个结构体的访问规则在其类型小节完整定义；并发章节只补充跨对象/跨上下文关系、锁顺序、临界区禁止操作或非结构体资源，没有重复访问表。
- [ ] 并发表只列本模块实际持有、读写或直接访问的资源；外部模块内部队列、缓存、来源槽和调度状态没有越界列入。

## 4. 事件交付语义决策

依次判断：

1. 通知类型是否已经表达状态或动作类别？若是，不重复携带同义字段。
2. 产品要求是“每次转换都必须保留”，还是“处理时只需要最新状态”？已明确选择逐事件快照语义或当前输出语义。
3. 逐事件快照语义下，发布方先确定本次动作，只携带最小值、动作或引用；接收方不按当前配置重新解释旧事件。
4. 当前输出语义下，发布方先原子更新输出再通知；事件可零载荷，接收方通过查询接口整体读取一致快照。
5. 当前输出语义已明确接受或拒绝以下行为：延迟事件读到最新值、中间输出被覆盖、多个通知合并。
6. 只有接收方确实需要完整配置时才考虑完整快照，并说明它解决的具体竞态。
7. 异步载荷默认值拷贝，禁止传递指向短生命周期对象的指针。
8. 已评估积压时延、通知失败和恢复策略；不会用当前查询值补造要求逐次执行的丢失动作。
