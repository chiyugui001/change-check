# 文件大小规范

> 团队知识库单文件体量唯一标准。
> 关联：[[团队知识库方案设计]] §2、[[知识库规范/层级架构规范]]、[[知识库规范/双链规范]]

---

## 1. 单文件单主题

- 一个 `.md` 文件只讲清**一个可独立检索的主题**，不把多个不相关主题塞进同一文件
- 主题大小以"能否用一句话回答这篇在讲什么"为判断：答不出或答成多句，就该拆
- 判断不了主题归属时，先看 [[知识库规范/层级架构规范]] 定层，再回来定体量

---

## 2. 行数阈值


| 档位  | 正文行数（不含 frontmatter / 代码块 / 图表） | 处理                               |
| --- | ------------------------------- | -------------------------------- |
| 推荐  | ≤ 300 行                         | 单文件承载，无需拆                        |
| 预警  | 300–500 行                       | 审视是否混入了多主题，能拆则拆                  |
| 强制  | &gt; 500 行                      | 必须拆分，按 [[知识库规范/层级架构规范]] 的层级拆成子文档 |


**⚠️ 行数一律指正文行数**——只数正文,frontmatter、代码块、Mermaid 图、表格都不计入。图表自身的繁简另按 [[知识库规范/图表规范]] §4 控制(单图 5–9 主节点,复杂拆多张)。

---

### 2.1 详设正文的文字长度与分行

- 适用于详设正文的纯文字说明，包括引用段和列表项；Markdown 表格、图片和代码块（含 Mermaid）不计入。
- 单行超过 120 个可见字符，或连续段落超过 200 个可见字符时，必须先精简重复和无信息增量的表述，再按独立要点分行。
- 分行使用 Markdown `- ` 无序列表，渲染为小圆点；每项一个要点，整项不超过 120 个可见字符。列表前留空行，不把整段原文仅加一个圆点。
- 连续段落指未被空行或 Markdown 块边界分隔的正文；仅在源码中换行仍算同段，多行列表项也合并计数。
- 汉字、字母、数字和标点各计 1 个字符；空白、格式标记和链接地址不计，链接显示文字与行内代码中的标识符计入。
- 精简必须保留条件、动作、时机、异常和结果，不拆断标识符，也不靠空行切段或添加无关图表规避超限。
- 相邻图表不豁免文字长度检查；图表已完整表达的内容不再逐句复述，仅补充理解所需的约束。
- 校验脚本只报告超限位置和长度，不自动删改正文；重复语义、要点拆分和约束是否完整由编写者复核。
- 编写或修改详设时，按 [[模板/详设]] 的入口运行文字校验。历史超限先报告；局部修改修正本次涉及的说明块，全篇修订修正全文。

## 3. 索引型文档不放实现细节

- `_INDEX.md`、总流程 SOP、`系统架构.md` 这类**MOC/导航型文档**（见 [[知识库规范/层级架构规范]] §2）只做主线串联 + 双链引用，**不放具体实现**
- 实现细节拆到叶子文档，在索引型文档里用 `[[叶子文档#章节|别名]]` 引用
- 反过来：叶子文档也不要重复抄索引型文档的主线，只展开自己的主题

---

## 4. 拆分后怎么连

- 拆出的子文档就近归位到所属功能/模块目录，不集中堆放，见 [[命名约定]] §3 决策就近原则
- 父文档用双链索引子文档；子文档不强制回链父文档（自上而下链接为主，见 [[知识库规范/层级架构规范]] §5）
- 一份内容只写一次、存一个文件;需要它的多篇文档各自用双链指过去,**不要把同一段正文复制到多处**——复制出的副本改一处、漏一处,迟早互相矛盾
- 拆分后更新所在目录的 `_INDEX.md`，保证每篇都被索引到、导航可达

## 5. 典型场景：总流程 SOP 过大

以固件研发总流程 SOP 为例，它把需求→详设→用例→物模型/IPSO→提测→验收→发布串成主线，**正文容易超 500 行**。按本规范处理：

- SOP 只保留：目的范围、角色、总流程图、各阶段**交接边界与卡点**、交付物清单
- 每个阶段的**具体实现工艺**（详设怎么写、IPSO 解析库怎么搭、提测循环 a1→a5 细则、需求澄清子流程细则）拆成独立主题文档
- SOP 里用 `[[详设阶段工艺#N. xxx]]`、`[[提测循环细则]]` 等双链引用（用文件名双链,不写死路径,文件迁移后链接不断）
- 拆出的文档统一归入 SOP 所在文件夹下按阶段分子目录;产品专属的实现放到对应**产品 SOP 文件夹**下(目录布局见 [[知识库规范/层级架构规范]] §6)

> 这样 SOP 只讲主线，实现细节随拆随链、各自演进、独立评审。

处理完后的文件布局（示意,展示拆分形状,非固定落点）:

```text
固件研发SOP/
├── _INDEX.md                 ← 局部索引,聚合各阶段入口
├── 固件研发总流程SOP.md       ← 只剩主线 + 交接卡点 + 交付物(正文回落到阈值内)
├── 详设/
│   ├── 详设阶段工艺.md        ← 从 SOP 拆出:详设怎么写、五模块并行怎么拆
│   ├── IPSO解析库设计.md
│   └── 物模型Toolbox验证.md
└── 提测循环/
    ├── 提测循环细则.md        ← 从 SOP 拆出:a1→a5 每轮动作
    └── 需求澄清子流程.md
```

拆分前后对照:实现工艺从 SOP 正文迁出成独立文档,SOP 只留一行 `[[详设阶段工艺]]` 双链;SOP 正文因此回落到阈值内,每份工艺文档各自单主题、可独立演进。

## 6. 自检清单

- [ ] 这篇能否一句话说清主题？说不清先拆
- [ ] 正文是否 &gt; 500 行（不含 frontmatter / 代码块 / 图表）？超了必须拆
- [ ] 是否在 MOC 文档里堆了实现细节？有就外迁成叶子文档
- [ ] 拆出的子文档是否就近归位 + 被上层双链索引 + 入 `_INDEX`？
