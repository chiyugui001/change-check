# 命名约定

> 团队知识库文件与目录命名唯一标准。
> 关联：[[团队知识库方案设计]] §4

---

## 1. 语言策略：中文优先，英文仅限两类

目录和文件名默认中文，只有两类必须用英文——通用约定文件和源码路径。

- **项目仓库**：仓库名使用产品代号或约定名称，如 `example-project`；仓库根目录不再嵌套 `项目/示例项目/`
- **通用知识区目录**：全中文，如 `通用/`、`平台/`、`模板/`、`知识库规范/`、`知识库架构/`
- **知识类型目录**：中文，如 `需求/`、`详设/`、`测试/`、`决策/`、`协议/`
- **功能目录**：中文，如 `温度告警/`、`开窗检测/`、`电机控制/`
- **普通知识文件**：中文，如 `阀门控制总时序.md`、`温度告警需求.md`
- **通用约定文件**：英文，如 `README.md`、`_INDEX.md`、`_DECISIONS.md`（跨项目通用的结构性文件，沿用英文惯例）
- **源码路径 / 代码符号**：英文（强制），如 `module_xxx`、`driver_xxx`，编译器不支持中文路径
- **协议名 / 芯片型号 / API / 产品代号**：英文，如 `AW9523B`、`IPSO-LPP`、`WT103`（专有名词本就是英文）

一句话：**能中文的地方都中文，只有 README/_INDEX 这类通用结构文件和源码路径用英文。**

---

## 2. 序号规则

- **文件和文件夹不带序号**：序号会带来维护困难，非必要不带
- **文档内部章节用序号**：章节标题用 `## 1. xxx`、`## 2. xxx` 编号

---

## 3. 决策文件命名

- 决策文件直接命名 `决策.md`
- 决策文件就近存放在功能/模块目录内，目录路径已表达上下文，文件名无需重复

---

## 4. 其他规则

- **不留空格**：中文名内部不留空格；中英混排用连字符或直接相连
- **改名同步双链**：改文件名后更新所有 `[[双链]]`，避免死链
